Diagram 3

➕ Sequence: POST Create Food

แสดงการไหลของ request เมื่อ Client สร้าง Food ใหม่

ขั้นตอน: Client ส่ง JSON → endpoint ตั้ง CORS → Controller ตรวจ input → Model validate() + INSERT → คืน id ใหม่ · ถ้า input ว่างเปล่า Controller ตอบ 422 ทันทีโดยไม่แตะ DB
sequenceDiagram autonumber actor C as Client participant E as foods.php participant FC as FoodController participant F as Food model participant DB as MySQL C->>+E: POST /foods.php { nameTh, category } E->>E: Set CORS Headers E->>+FC: handle("POST", body) FC->>FC: ตรวจ nameTh ว่าง? FC->>FC: ตรวจ category ว่าง? alt Validation fails FC-->>C: 422 { success:false, error } else Valid input FC->>+F: init(nameTh, category) F-->>-FC: set properties FC->>+F: create() F->>F: validate() F->>+DB: INSERT INTO foods VALUES(?,?) DB-->>-F: lastInsertId = 4 F-->>-FC: return 4 FC-->>-E: Response::created({id:4,...}) E-->>-C: 201 { success:true, data:{id:4,...} } end
Diagram 4

🔍 Sequence: GET Food by ID

แสดงการดึง Food พร้อม recipeList ผ่าน LEFT JOIN

display() ใช้ LEFT JOIN ระหว่าง foods และ recipes ดึงมาเป็นหลาย row แล้ว loop สร้าง recipeList[] — ถ้าไม่พบ food ตอบ 404 ทันที
sequenceDiagram autonumber actor C as Client participant E as foods.php participant FC as FoodController participant F as Food model participant DB as MySQL C->>+E: GET /foods.php?id=1 E->>+FC: handle("GET", {id:1}) FC->>FC: id = (int)"1" = 1 FC->>FC: ตรวจ id > 0 FC->>+F: food.id=1, display() F->>+DB: SELECT f.*, r.*\nFROM foods f\nLEFT JOIN recipes r ON f.id=r.food_id\nWHERE f.id=1 DB-->>-F: หลาย rows (1 food, N recipes) F->>F: loop rows → recipeList[] alt ไม่พบข้อมูล F-->>FC: null FC-->>C: 404 { success:false, error } else พบข้อมูล F-->>-FC: { id, nameTh, category, recipeList:[...] } FC-->>-E: Response::success(food) E-->>-C: 200 { success:true, data:{...recipeList} } end
Diagram 5

🗑️ Sequence: DELETE Food

แสดงการลบ Food และ ON DELETE CASCADE ที่ลบ Recipes ด้วยอัตโนมัติ

ก่อนลบ Controller เรียก exists() ตรวจก่อนว่า Food มีอยู่จริง — ถ้าไม่มีตอบ 404 ทันที · เมื่อลบ Food MySQL จะลบ recipes ที่ food_id ตรงกันด้วยผ่าน ON DELETE CASCADE
sequenceDiagram autonumber actor C as Client participant E as foods.php participant FC as FoodController participant F as Food model participant DB as MySQL C->>+E: DELETE /foods.php?id=2 E->>+FC: handle("DELETE", {id:2}) FC->>FC: id=2, ตรวจ id > 0 FC->>+F: food.id=2, exists() F->>+DB: SELECT id FROM foods WHERE id=2 DB-->>-F: row / empty alt ไม่พบ Food F-->>FC: false FC-->>C: 404 { success:false, error } else พบ Food F-->>-FC: true FC->>+F: delete() F->>+DB: DELETE FROM foods WHERE id=2 Note over DB: ON DELETE CASCADE\nลบ recipes.food_id=2 ทั้งหมด DB-->>-F: rowCount=1 F-->>-FC: true FC-->>-E: Response::success({id:2,...}) E-->>-C: 200 { success:true,\ndata:{id:2, message:"deleted"} } end
Reference

📡 API Reference

สรุป endpoints ทั้งหมดพร้อม HTTP method และ response status

Base URL: http://localhost/food-recipe-api/api/endpoints/ · ทุก response มีรูปแบบ { "success": bool, "data"|"error": ... }
Method Endpoint Query / Body สิ่งที่ทำ Status
GET /foods.php — ดู Food ทั้งหมด 200
GET /foods.php ?id=1 ดู Food + recipeList (display) 200 / 404
POST /foods.php { nameTh, category } สร้าง Food ใหม่ 201 / 422
PUT /foods.php { id, nameTh, category } แก้ไข Food 200 / 404 / 422
DELETE /foods.php ?id=1 ลบ Food + Cascade Recipes 200 / 404
GET /recipes.php ?food_id=1 ดู Recipes ทั้งหมดของ Food 200
GET /recipes.php ?id=1 ดู Recipe เดี่ยว 200 / 404
POST /recipes.php { food_id, recipeName, quantity, unitName } เพิ่ม Recipe (addRecipe) 201 / 422 / 404
PUT /recipes.php { id, recipeName, quantity, unitName } แก้ไข Recipe 200 / 404
DELETE /recipes.php ?id=1 ลบ Recipe 200 / 404
